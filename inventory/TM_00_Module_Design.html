Stock Management by Transaction Mode — Module Design BLUEPRINT

Yarn Inventory · Epyllion Textile ERP · design note accompanying the four interface mockups · 16-Sep-2026

1 · The idea in one paragraph

Instead of programming a separate screen for every kind of stock movement (issue, return, transfer, loan, adjustment…), the store defines each movement once as a Transaction Mode: what type it is (Addition, Deduction or Both), which Stock Registers it may take from and put into, whether it can cross units, which upstream Reference Input it must cite, and whether it needs approval. The Daily Transaction screen then reads that setup and shows only the fields the chosen mode allows. Every approved document writes ledger effects on (lot, unit, register) cells; the Stock Register Ledger and Dashboard are pure reads of those cells. Adding a new business movement becomes a setup task, not a development task.

The fields below reproduce the reference sheet; rows tagged ADDED are recommendations that make the setup complete enough to drive the entry screen without further programming.

Setup validations

  • Name and short name unique across modes; type mandatory.
  • Deduction / Both need ≥ 1 From register; Addition / Both need ≥ 1 To register.
  • Both, not multi-unit, with the same single register on both sides is rejected (nothing could move).
  • “Has reference” with N/A selected is rejected.

3b · Stock form rule — Intake and Lose

Stock is always kept in two forms, and every quantity field carries six figures: Intake Carton, Intake Cone, Intake Kg (unopened original packing) and Lose Carton, Lose Cone, Lose Kg (opened cartons and loose cones). Total Kg = Intake Kg + Lose Kg is the posting basis for balances, statements and the dashboard; cartons and cones are tracked alongside so the store can count what is physically on the rack.

WhereRule
Lot masterEach lot carries cones per carton and kg per cone. Intake cartons → cones → kg follow this packing automatically; Lose kg can be typed for part cones.
Register cell(lot, unit, register) holds a six-figure pack. Balance, Committed and Available are all per form; a deduction may not exceed Available in any of the six figures.
Pick from stockPer lot: available Intake and Lose, then six pick inputs. Auto-pick takes full intake cartons first, then loose.
Floor ReturnAlways comes back in Lose form.
Carton Break (TM-014, type Form Conversion)The store opens n intake cartons of a lot inside one register cell: Intake −n ctn / cones / kg, Lose +n ctn / cones / kg. Register kg does not change; the lot ledger shows the shift in the form columns.
RequisitionThe floor asks in Kg and Cone only; the store decides which form to issue from.

Entry validations (from the mode + stock)

  • From / To register must be among the mode's ticked registers; unit rule follows Multi Unit.
  • Reference document mandatory when the mode says so; the list offers only open documents of that type.
  • Every deduction line ≤ Available of (lot, unit, register). Available already excludes Pending Approval commitments.
  • Adjustment modes require evidence text in Remarks and always go through approval.
  • Changing mode, unit or From register after lines exist clears the lines — the lots were valid only for that cell.

Yarn rows and stock picking

  • With a reference (Knitting / YD Requisition, Transfer Requisition, Loan Issue Request) — selecting the document copies unit, party and order and sets one yarn row per line with description, spinner, lot, physical count and required quantity. Each row has a Pick from stock button opening a modal that lists that yarn's lots / locations in the From cell with balance and available; the user ticks several, types a quantity per lot (an Auto-pick FIFO button fills them by receipt date) and presses OK. The row shows the picked lots and the summed quantity, flagged when short of or over the reference.
  • Return Note, Loan Receive Request (Addition) — the document names the lot, so the row becomes the line directly; Edit reopens it in the add-yarn modal.
  • Without a reference — an Add Yarn button opens a modal. For Deduction / Both it lists yarns with available stock in the From cell; selecting one adds the row and opens the same pick modal. For Addition it asks yarn, spinner, lot (known or new), count and quantity.
  • The ledger always posts lot-level lines, so a yarn row picked from three lots writes three ledger effects and shows as three grid rows in the list.

6 · How stock is managed

Stock cell(lot, unit, register). A lot can sit in several cells at once, e.g. 2,400 kg Allocated + 600 kg M&M Projection in EFL. BalanceOpening balance + Σ ledger effects of Approved documents dated ≤ as-of date. Never stored, always recomputed, so the ledger can be re-run for any date. CommittedΣ deductions of Pending Approval documents on that cell. AvailableBalance − Committed. This is the number the entry screen validates against and the pick-list shows. Lot ledgerOpening + every effect on that lot in date order with a running balance; a transfer shows Out and In on the same document number. StatementPer register: opening (before From date), In, Out, Closing and the modes that moved it — the monthly stock statement the Excel sheets produced by hand.

10 · Decisions to confirm

  1. Loan between units: modelled as one Both-type document (lender's register → borrower's Liability). If each unit must book independently, keep Loan Issue Request and Loan Receive Request as two Addition / Deduction modes instead.
  2. Receipt from spinner stays in the MRIR / GRN module; this module starts after GRN. If a “Yarn Receive” mode is wanted here for opening or non-PO stock, it is a plain Addition mode.
  3. Who approves: currently one role (Store Manager). Per-mode approver or amount-based approval is a small extension of the Approval Required flag.
  4. Physical Count is carried per lot from receipt; if it must be re-entered per transaction (as the reference grid suggests), the line keeps its own value — the entry screen already allows this for new lots.
  5. Register master is fixed at six here; if stores need to add registers themselves, TM_01's Stock Registers tab becomes editable with the same activate / deactivate rule as modes.
